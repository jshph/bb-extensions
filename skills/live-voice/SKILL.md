name: live-voice
description: Explain or troubleshoot the Live Voice plugin, shared Codex/Claude controls, subscription authentication, and delegation lifecycle.
---

Live Voice is the provisional name of the shared voice UI for Codex and Claude threads. Start it from the waveform next to dictation. Mute affects microphone capture. End closes voice while leaving submitted coding work running. Stop agent explicitly requests cancellation; completed actions are not undone.

Codex uses the existing native provider connection through BB’s threads.voice bridge. The plugin must not open another writer for that coding thread or re-execute native delegations. The local customized BB has the bridge; stock-BB native compatibility is not established. A missing bridge fails explicitly.

Claude uses a temporary Codex app-server only to negotiate subscription-authenticated browser audio, then detaches it and delegates to the selected BB thread. It requires Codex ChatGPT sign-in on the BB server. Use codex login status without reading credentials. The executable setting can select the official CLI when a shell wrapper changes accounts. API keys and API billing fallback are unsupported.

Claude result delivery is event driven and incremental. A follow-up can steer voice-owned active work; unrelated active tasks are not silently queued or steered. Tool approvals stay in BB. Raw reasoning and tool logs are not streamed as speech. Context instructions are agent-only, apply to voice requests, and are sent once after provider acceptance. New handoffs carry only new or corrected spoken turns. Existing historical wrappers remain unchanged.

Use bb plugin rpc inspect live-voice for available, start, stop, context, poll, delegate, and control schemas. start needs caller-supplied WebRTC SDP; poll supports afterSeq; control accepts cancelWork. The CLI does not record or play voice.

Use bb plugin list and bb plugin logs live-voice for health. Rebuild with npm run check, npm test, and bb plugin build . before reload. Start a fresh call after upgrades. Do not claim exhaustive whole-thread coverage, general stock-BB compatibility, rollback of completed actions, or physical-device verification that has not happened.


Diagnostics default to basic, frozen per call: lifecycle/failure categories, connection/playback/mute, turn boundaries, startup cache metadata, and first/final delegation milestones. Basic excludes transcripts, exact context/request/result text, individual deltas and chunk timing before browser send and again at server ingestion. Use bb plugin config live-voice set diagnostics detailed for a fresh troubleshooting call, then restore basic. Detailed captures private text/timing; never raw audio/SDP/credentials/reasoning. Legacy full context can include source/tool material. No tracing path changes prompts, synthesis usage or endpointing.

traceSessions ({threadId?}) reports the frozen diagnostics policy; traceRead ({sessionId, afterId?:0}) pages with the last cursor until empty. trace accepts browser batches, not voice commands. Local plugin DB retention: 20 calls/seven days, 256,000 serialized bytes/basic call or 2,000,000/detailed, with 32,000 bytes reserved for stop/failure evidence. SQLite/index/WAL overhead and product briefings are additional. Existing detailed traces age out normally; no purge occurs. Warnings are rate-limited once/minute/call or browser collector. Dropped counts, truncation flags, browser sequence gaps and unsaved exit batches indicate incomplete evidence; server sequence is global, so per-call server gaps alone do not establish loss.

Startup records attempted cache state/age/fingerprint/length, with exact framing only in detailed mode. session.connect means negotiation succeeded; acknowledgements do not prove model attention and playback allowed does not prove physical output. Native observation cannot verify outgoing wire delivery. Claude detailed chunks correlate updateSeq; keep its functional streaming/poll/notifications. Basic native observation retains functional turn/state events but excludes diagnostic-only deltas. Browser elapsedMs is monotonic; server elapsedMs uses wall time. Compare fresh detailed calls with identical opening words and devices when diagnosing unsolicited responses.

Version 0.2.2 adds backgroundMode: off, briefing (the 0.2.2 default; 0.3.0 defaults to off), full; configure with bb plugin config live-voice set backgroundMode <mode>. Changes apply only to new calls; context.policy records the frozen mode. Off suppresses both plugin background delivery routes without changing native instructions/delegation. Briefing uses a bounded latest-answer excerpt (2,000 characters, no fenced code), not a semantic whole-thread summary; full restores the previous context path. For diagnosing unsolicited affirmations, compare fresh calls on the same thread with identical opening words and a 15-second pause, off first and briefing second. Acknowledged context appends can still affect behavior; do not promise silence. Inspect traces before attributing symptoms to endpointing. The local installation may intentionally be set to off for baseline testing.


Version 0.3.0 adds experimental backgroundMode cached. The plugin synthesizes structured goals, decisions, findings with source event pointers, and open questions using an isolated subscription-authenticated Codex session. Only fresh briefings enter initialItems before audio connects, on both adapters; no cached-mode midcall append occurs. A miss/stale/busy/error uses retrieval-only for the entire call and prepares the next call without waiting for a model at startup. Voice-used or explicitly prepared threads refresh when idle. Active work invalidates the cache. Source selection: latest 12 user requests and 100 root completed items after context clear, 60,000 characters total, 6,000 per item; includes tool results but excludes reasoning, nested agents and agent-only wrappers. Output is at most 3,000 JSON characters / 4,000 framed. Coverage is bounded, not exhaustive; synthesis can lose facts. One compiler job at a time, 90-second deadline, ChatGPT subscription only. Cache retention is 20 threads / seven days, freshness 24 hours plus matching semantic thread revision. Cached native calls additionally require startup-briefing bridge / host protocol 269. Do not silently downgrade missing native capabilities.

RPC briefingStatus, prepareBriefing and forgetBriefing accept {threadId}. Status returns missing/busy/preparing/ready/stale/error; only ready includes text. Prepare registers a watch and queues work when idle; it can explicitly prepare while background is off. Forget deletes cache and watch. Switching away from cached cancels pending synthesis. start returns optional briefing ready/lookup; context.startup records attempted cache metadata, adding the exact ready reference only in detailed mode. UI displays briefed/context on request. Use bb plugin config live-voice set backgroundMode cached or off, then start a new call. Generated findings and transcripts are private local plugin data. Never equate injected context with guaranteed model attention or silent behavior.
